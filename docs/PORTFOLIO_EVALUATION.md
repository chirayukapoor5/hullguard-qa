# Portfolio evaluation

This review assesses the portfolio artifact for a software tester trainee conversation. It represents an independent perspective.

## HR recruiter

The portfolio makes an MSc AI and computer science background relevant by showing a real engineering testing workflow, a visible design revision, and a clear explanation of scope. The best conversation starter is the stale BOM: one editable part, a checked 31.4 kg change and a traceable failure. The project provides evidence of learning engineering terminology. Evidence of real ship-design tool use, work with naval architects and shipping-domain practice remains a gap.

## Technical lead

The risk register and traceability map explain which cases matter and why. A tester can reproduce the six defects, compare revisions, and inspect the code and evidence. Browser acceptance, automated reporting and the manual plan cover different parts of the workflow. Human execution of the manual suite, cross-browser testing and feedback from another reviewer would strengthen the evidence.

## Principal engineer

The plate reference, exact assembly sum, mesh-volume calculation and current-revision content mutations show good judgment for an entry-level testing portfolio. The cases are inspectable and reproducible, and the simplifications are visible. The parser, geometry model and SVG checks deliberately cover a bounded subset. A formal domain review and interoperability exercise would be needed before applying the reasoning to a wider class of production artifacts. Coverage is a record of executed code and gives no assurance about engineering rules outside the fixture scope.
